# Doc Forge — генератор фирменных документов v-b.tech

**Дата:** 2026-08-28 · **Статус:** утверждён

## Цель

Защищённая паролем страница на v-b.tech: вводишь данные документа — получаешь
готовый фирменный `.docx` с уникальным баркодом (и баркод отдельно как PNG/SVG).
Опционально документ выходит «подписанным»: с оттиском печати и факсимиле подписи.

## Контекст

- Сайт: `apps/web`, Astro 7, `output: "static"` — серверного рантайма нет.
- Фирменный баркод детерминированный (FNV-1a → mulberry32), уже используется на
  сайте-прототипе, в Word-ассетах и печатях. Посеянный от данных документа, он даёт
  каждому документу уникальный воспроизводимый «отпечаток».
- Word-шаблон бренда уже описан кодом (docx-js) в `brand/word/build_template.cjs`
  (вне монорепо, в облачной папке бренда) — структура переносится в браузер.
- В инструмент включаются приватные ассеты (подпись, печать) — на статическом
  хостинге они не должны лежать в открытом виде.

## Решение: «шифрованный остров»

Страница `/tools/doc/` отдаёт только форму пароля и зашифрованный блоб с
инструментом. Пароль → PBKDF2 (600k итераций, SHA-256) → AES-GCM → расшифровка
в памяти → `import()` бандла из blob-URL. Без пароля на хостинге лежит только
шифротекст. После загрузки инструмент работает полностью офлайн (по-брендовски).

Отвергнутые альтернативы: клиентский гейт с хэшем пароля (ассеты подписи/печати
остаются в public открыто — неприемлемо); перевод сайта на SSR-адаптер ради
одной страницы (меняет модель деплоя всего статического сайта).

## Архитектура

```
apps/web/
├── src/pages/tools/doc.astro          # оболочка: unlock-форма, noindex
├── src/tools/doc-forge/               # исходники инструмента (vanilla TS)
│   ├── main.ts                        # UI: форма, превью, кнопки скачивания
│   ├── barcode.ts                     # FNV-1a + mulberry32 + отрисовка canvas/SVG
│   ├── docx-factory.ts                # сборка .docx (библиотека docx в браузере)
│   ├── assets/                        # base64: пилюля-тире, печать, подпись
│   └── unlock.ts                      # PBKDF2 + AES-GCM decrypt, sessionStorage
└── scripts/build-doc-forge.mjs        # esbuild-бандл → шифрование → public/tools/doc-payload.bin
```

- Сборка блоба — prebuild-скрипт (`node scripts/build-doc-forge.mjs`, вызывается
  из npm-скрипта `build` перед `astro build`) с паролем из env
  `VBTECH_DOC_TOOL_PASSWORD`; в репозиторий пароль не попадает. Без выставленного
  пароля сборка страницы пропускается с предупреждением (сайт собирается как есть).
- Инструмент — vanilla TS, без фреймворка (в repo нет React).

## UI

Форма:
- Тип документа: спецификация / КП / протокол / письмо — задаёт eyebrow-метку и
  стартовую структуру тела документа.
- DOC-ID: автоподсказка следующего номера `DOC-2026-NNN` (счётчик в localStorage).
- Название, автор (предзаполнен из localStorage), дата (сегодня), статус draft/final.
- Чекбокс «печать + подпись».

Справа — живое превью титульного блока и баркода. Кнопки: «Скачать .docx»,
«Баркод PNG», «Баркод SVG». Имя файла: `DOC-2026-001 — Название.docx`.

## Генерация

- Баркод: сид `«{DOC-ID} {название}»`, алгоритм и пропорции — фирменные
  (ширины 2·3·5·8·12, один янтарный штрих #F5A623). Canvas → PNG; строка → SVG.
- `.docx`: структура фирменного Word-шаблона — стили (Title, Eyebrow, H1–H3,
  цитата, код), колонтитулы (крупный на первой странице, компактный дальше),
  титульный блок с введёнными данными, баркод документа в футере, блок
  согласования. При опции — синяя печать + факсимиле над линией подписи.

## Приватность и данные

- Пароль и приватные ассеты — только внутри шифроблоба.
- localStorage: имя автора, счётчик DOC-ID. sessionStorage: ключ сессии разблокировки.
- Бэкенда и телеметрии нет. Клиентские цифры/NDA-контент инструмент не содержит.

## Ошибки

- Неверный пароль → «не расшифровалось», поле очищается.
- Web Crypto требует secure context (https/localhost) — выполняется на v-b.tech;
  на http-превью показываем понятное сообщение.

## Тесты (vitest, уже в repo)

- Детерминизм баркода: снапшот последовательности штрихов для эталонного сида.
- Roundtrip: encrypt (скрипт сборки) → decrypt (unlock.ts).
- Smoke docx-фабрики: результат — валидный zip, содержит DOC-ID/название/автора.

## Ограничения v1 (осознанные)

- Счётчик DOC-ID локальный, между устройствами не синхронизируется
  (реестр документов — отдельный проект).
- Один общий пароль без ролей.
- PDF/PPTX-выходы — вне скоупа v1.
